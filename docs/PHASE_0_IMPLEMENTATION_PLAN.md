**Source of truth:** `docs/POSTGRESQL_DATABASE_SPECIFICATION.md` Part 3 (Table Specifications) and Part 6 (Index Design).

**Key decisions:**

| Decision | Choice | Rationale |
|---|---|---|
| Provider | `postgresql` | Target database |
| Generator | `client` (JS, ESM) | Project uses ESM (`"type": "module"`) |
| ID strategy | `uuid` | PG native UUIDs, replaces PB's 15-char IDs |
| Decimal fields | `Decimal` (Prisma) | Maps to `DECIMAL(10,2)` in PG |
| JSON fields | `Json` (Prisma) | Maps to `JSONB` in PG |

### 4.2 Prisma Client Singleton (`src/lib/prisma.js`)

**What:** A singleton module that initializes and exports a single PrismaClient instance.

```js
// src/lib/prisma.js
import { PrismaClient } from '@prisma/client';
import logger from '../utils/logger.js';

const globalForPrisma = globalThis;

const prisma = globalForPrisma.prisma ?? new PrismaClient({
  log: [
    { emit: 'event', level: 'query' },
    { emit: 'stdout', level: 'error' },
    { emit: 'stdout', level: 'warn' },
  ],
});

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma;
}

// Log slow queries (>500ms)
prisma.$on('query', (e) => {
  if (e.duration > 500) {
    logger.warn(`[PRISMA] Slow query (${e.duration}ms): ${e.query}`);
  }
});

export default prisma;
```

**Pattern:** `globalThis` caching prevents multiple Prisma instances in development with hot module reload.

### 4.3 Event Bus (`src/lib/eventBus.js`)

**What:** In-process event emitter for cross-service communication. Replaces PocketBase's hook system.

```js
// src/lib/eventBus.js
import { EventEmitter } from 'node:events';

class EventBus extends EventEmitter {
  constructor() {
    super();
    this.setMaxListeners(50); // Temple app has ~17 event subscriptions
  }

  emit(event, data) {
    logger.info(`[EVENT] ${event}`, data ? JSON.stringify(data).slice(0, 200) : '');
    return super.emit(event, data);
  }
}

const eventBus = new EventBus();
export default eventBus;
```

### 6.3 Email Queue Table

The `emailQueue` table acts as the persistent queue:

| Operation | SQL |
|---|---|
| Queue email | `INSERT INTO email_queue (to, subject, template, data, status, attempts)` |
| Process | `SELECT * FROM email_queue WHERE status = 'pending' ORDER BY createdAt LIMIT 10` |
| Mark sent | `UPDATE email_queue SET status = 'sent', sentAt = now()` |
| Mark failed | `UPDATE email_queue SET attempts = attempts + 1, lastError = $error` |
| Dead letter | `UPDATE email_queue SET status = 'dead_letter' WHERE attempts >= 3` |

### 6.4 Retry Strategy

| Attempt | Delay | Action |
|---|---|---|
| 1st | Immediate | Send email |
| 2nd | 10 minutes | Retry |
| 3rd | 30 minutes | Retry |
| 4th (final) | 60 minutes | Retry, then dead letter |

## 7. Step 0.5: JWT Middleware

**What:** JWT authentication middleware replacing PocketBase's built-in auth.

**Source:** `docs/SECURITY_ARCHITECTURE_BLUEPRINT.md` Part 2 (Authentication Architecture).

**Files:**
- `apps/api/src/middleware/jwt.js` — Express middleware
- `apps/api/src/middleware/rbac.js` — Role-based access control

### 7.1 JWT Configuration

| Property | Value |
|---|---|
| Access token lifetime | 15 minutes |
| Refresh token lifetime | 7 days |
| Algorithm | HS256 (symmetric) |
| Secret | `JWT_SECRET` env var (64+ char random string) |
| Issuer | `vinayagar-temple` |
| Token storage (client) | Access: memory/localStorage; Refresh: httpOnly cookie |
| Token transmission | Authorization: Bearer (access); Cookie (refresh) |

### 7.2 JWT Middleware (`jwt.js`)

```js
// Flow:
// 1. Extract Authorization header
// 2. Verify Bearer token format
// 3. Verify JWT signature + expiry using jsonwebtoken
// 4. Attach decoded payload to req.user
// 5. Check user still exists and is not deleted/blocked
// 6. Call next()

// Does NOT throw for missing token (allows optional auth)
// Throws AuthenticationError for invalid/expired tokens on protected routes
```

**Key difference from current `auth.js`:** Current middleware does manual base64 decode and PocketBase fetch. New middleware uses `jsonwebtoken` for proper signature verification and fetches from PostgreSQL via Prisma.

### 7.3 RBAC Middleware (`rbac.js`)

```js
// Usage: router.get('/admin/users', jwt, requireRole('admin'), handler)
// Or:    router.get('/my-bookings', jwt, requireRole('user', 'admin'), handler)

function requireRole(...allowedRoles) {
  return (req, res, next) => {
    if (!req.user) return next(new AuthenticationError('Authentication required'));
    if (!allowedRoles.includes(req.user.role)) {
      return next(new AuthorizationError('Insufficient permissions'));
    }
    next();
  };
}
```

### 7.4 Token Lifecycle

| Event | Token Action | Server Action |
|---|---|---|
| Login | Generate access (15m) + refresh (7d) | Store refresh token hash |
| Refresh | Rotate refresh token, issue new access | Revoke old refresh token |
| Logout | Client discards tokens | Revoke refresh token |
| Password change | — | Revoke ALL refresh tokens for user |
| Admin block | — | Revoke ALL refresh tokens for user |

### 7.5 Coexistence with PocketBase Auth

During migration, both auth systems coexist:

- **Existing routes** (in `routes/index.js`): Continue using `authMiddleware` from `./middleware/auth.js` (PB-based)
- **New routes** (Phase 1+): Use `jwt` middleware from `./middleware/jwt.js` (JWT-based)
- **Frontend**: Phase 1 replaces `AuthContext` and `pocketbaseClient.js`

The `authMiddleware` (PB) and `jwt` middleware (JWT) can coexist because both set `req.user` with the same shape: `{ id, email, name, role }`.

## 10. Step 0.8: Validation Middleware (Zod)

**What:** Request input validation using Zod schemas.

**File:** `apps/api/src/middleware/validate.js`

### 10.1 Design

```js
import { z } from 'zod';

// validate(schema, source = 'body')
// source: 'body' | 'query' | 'params'
function validate(schema, source = 'body') {
  return (req, res, next) => {
    const result = schema.safeParse(req[source]);
    if (!result.success) {
      return next(new ValidationError('Invalid input', result.error.issues));
    }
    req[source] = result.data; // Use parsed (coerced) values
    next();
  };
}
```

### 11.1 Error Classes (`lib/errors.js`)

```js
export class AppError extends Error {
  constructor(message, statusCode, code, details = null) {
    super(message);
    this.name = this.constructor.name;
    this.statusCode = statusCode;
    this.code = code;
    this.details = details;
    Error.captureStackTrace(this, this.constructor);
  }
}

export class ValidationError extends AppError {
  constructor(message, details) {
    super(message, 400, 'VALIDATION_ERROR', details);
  }
}

export class AuthenticationError extends AppError {
  constructor(message = 'Authentication required') {
    super(message, 401, 'AUTHENTICATION_ERROR');
  }
}

export class AuthorizationError extends AppError {
  constructor(message = 'Insufficient permissions') {
    super(message, 403, 'AUTHORIZATION_ERROR');
  }
}

export class NotFoundError extends AppError {
  constructor(entity = 'Resource', id = null) {
    super(
      id ? `${entity} with id '${id}' not found` : `${entity} not found`,
      404,
      'NOT_FOUND'
    );
  }
}

export class ConflictError extends AppError {
  constructor(message) {
    super(message, 409, 'CONFLICT');
  }
}

export class BusinessRuleError extends AppError {
  constructor(message) {
    super(message, 422, 'BUSINESS_RULE_VIOLATION');
  }
}

export class ExternalServiceError extends AppError {
  constructor(service, message) {
    super(`${service}: ${message}`, 502, 'EXTERNAL_SERVICE_ERROR');
  }
}
```

### 11.2 Error Handler (`middleware/errorHandler.js`)

```js
export default function errorHandler(err, req, res, next) {
  // If it's an AppError subclass, use its properties
  if (err instanceof AppError) {
    return res.status(err.statusCode).json({
      success: false,
      error: {
        code: err.code,
        message: err.message,
        ...(err.details && { details: err.details }),
      },
    });
  }

  // Zod errors (from validation middleware)
  if (err.name === 'ZodError') {
    return res.status(400).json({
      success: false,
      error: {
        code: 'VALIDATION_ERROR',
        message: 'Invalid input',
        details: err.issues,
      },
    });
  }

  // Prisma errors
  if (err.code === 'P2025') {
    return res.status(404).json({
      success: false,
      error: { code: 'NOT_FOUND', message: 'Record not found' },
    });
  }

  // Unexpected errors — log and return generic message
  logger.error(`[ERROR] ${err.message}`, err.stack);
  return res.status(500).json({
    success: false,
    error: {
      code: 'INTERNAL_ERROR',
      message: process.env.NODE_ENV === 'production'
        ? 'An unexpected error occurred'
        : err.message,
    },
  });
}
```

| Service class names | PascalCase + `Service` | `StorageService`, `AuditService` |
| Service methods | camelCase | `approve()`, `generateReceipt()` |
